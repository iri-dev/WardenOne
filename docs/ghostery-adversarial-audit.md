# G-08 adversarial boundaries and failure

The source-derived endpoint census is `docs/message-boundaries.json`. It records worker message and port listeners, content and page-world bridges, message kinds, and manifest web-accessible resources. The manifest has no `externally_connectable` declaration. `docs/message-security-audit.md` explains the sender and payload policy; the current inventory is checked by the maintainability gate after each source change.

The worker treats a content script as a tab sender, not a privileged extension page. `tools/test-message-boundaries.js`, `tools/test-message-hardening.js`, `tools/test-message-reachability.js`, and `tools/browser-message-boundaries.js` exercise denied settings, broad allowlisting, data reads, network operations, malformed payloads, subframes, and web-accessible warning pages. In a disposable Edge 150.0.4078.48 profile, the native test denied 102 private message kinds from an isolated tab context while the popup retained its authorized health read. The page-to-bridge config tests reject forgery, replay, changed signed content, changed host lists, and a stale config after a refreshed worker snapshot. The browser test supplies native sender identity; the signed-config test models the bridge protocol in process.

The remote option parser now skips regex-literal rules it cannot execute and rejects malformed `domain=` labels or extra equals signs. Rejected lines consume neither rule IDs nor the option-rule quota. `tools/test-filter-compilation.js` runs consecutive unsupported regexes and malformed scopes before valid rules, then checks the capped output and contiguous IDs. `tools/test-user-filters.js` checks the same consecutive-regex boundary in reader-authored custom rules. Unknown filter syntax remains uninstalled. Existing integrity tests reject malformed or oversized remote lists as complete sources and preserve the last accepted data.

The results do not establish behavior in every Chromium version or on arbitrary websites. The full source and regression gate is recorded in `docs/ghostery-adversarial-evidence.json`.
