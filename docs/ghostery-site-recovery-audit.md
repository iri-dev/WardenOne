# G-07 guided site recovery

The **Site not working?** panel uses the current tab's Site Dashboard observations. It offers up to three protections that recorded a mapped action in the last ten minutes. A suggestion is evidence of an action, not proof that the action caused breakage. If no lower-risk action was recorded, the panel says so and points to Activity and the existing site controls. A link opens Network Logger for users who want to reproduce the problem and inspect a single matching request before allowing its rule. The panel never changes a setting without a user click.

The trial is one feature on the current **host and its same-site subdomains** for 15 minutes. The fixed candidate set covers ad, tracker, third-party cookie, consent, overlay, scriptlet, link-cleaning and autoplay behavior. Malware, phishing, token-exfiltration and payment-theft protections are absent from that set. The worker accepts trial messages only from its own popup, reads the active tab from Chrome, rejects browser pages, private windows, private/local hosts and public suffixes, and refuses an already-disabled or concurrently active trial. A separate existing site override remains untouched. The regular pause and lasting override controls remain available below the guided flow.

`siteRecoveryUntil` stores only the host, feature key and expiry in local configuration. The worker validates those fields, overlays the temporary false value onto its effective config, and excludes the trial metadata from page snapshots and settings backups. Expired entries stop affecting decisions on read. The existing site-expiry alarm invalidates cached content config and reconciles browser rules; the next recovery change prunes expired stored entries. Undo deletes the trial immediately. A browser restart reloads an unexpired trial from local configuration. Site-data erasure removes the targeted host's trial while retaining other sites' choices.

The diagnostic is built from the existing page summary. Its preview contains only the exact host, recognized recent action types and counts, and an active trial's feature and expiry. It omits event detail, page text, full URL, path, query, passwords and screenshots. The popup creates a local JSON file only after the user presses **Save diagnostic file**. No report is sent from the extension.

## Verification

`tools/test-site-recovery.js` checks expiry, safe candidate mapping, public suffix and hosted-tenant boundaries, lookalike hosts, preservation of lasting overrides, and report redaction. `tools/test-message-boundaries.js` rejects a content-script attempt to start a trial. `tools/test-settings-io.js` verifies trials cannot enter settings backups or imports. `tools/test-privacy-data-erase.js` checks targeted trial removal.

`tools/browser-site-recovery.js` ran in a disposable Edge 150.0.4078.48 profile with a local fixture and other DNS denied. A recorded overlay action produced one suggested feature. The actual worker and content snapshot used the temporary override without changing the lasting site settings; a user-started reload retained it. Auth, payment, media and separate hosted-tenant fixture hosts showed no spillover; the media fixture played. A browser settings page was rejected. The diagnostic preview dropped synthetic path/query/fragment secrets. Undo and reload restored the original setting. A separate third-party-cookie trial appeared in Chromium's installed session rule, disappeared on undo, survived a full browser restart, and disappeared at expiry; the worker and content view agreed. The accepted report is `tmp/ghostery-phase07/browser-network.json`.

The native fixture does not establish that an arbitrary real website works with a trial. The flow offers only a feature whose action was observed, so the user can test and undo it; player sites are not exempted or changed by default. The source-derived inventories and full maintainability gate are recorded in `docs/ghostery-site-recovery-evidence.json`.
